# MOOSEDev v0.12.0

v0.12.0 moves MOOSEDev onto MOOSE v0.29.0, closes the local HTTP API to other websites, and makes dossiers and recall more precise about which knowledge applies.

## Highlights

### Updated engine

MOOSEDev now builds against MOOSE v0.29.0. Most of the change shows up in `query` and the workbench chat:

- **Answers use the ontology's own words.** Answer rows name properties by their ontology labels rather than their internal identifiers.
- **More clarifying questions and refusals.** Some questions that used to get an answer now end with a clarifying question or a refusal, because they cannot be answered as asked.
- **Turns have a time limit.** A question that runs longer than 120 seconds is stopped. `query` returns an error asking for a narrower question, and a workbench chat turn answers HTTP 504.

### The HTTP API refuses other websites

Before this release, the daemon's HTTP API allowed cross-origin requests from any origin. A web page open in the user's browser could call it, including the routes that change the graph. Every request now passes an Origin/Host check:

- The `Host` must be an IP address or `localhost`, which closes off DNS rebinding.
- A browser `Origin` must match the daemon's own address or be listed in the new `MOOSEDEV_ALLOWED_ORIGINS` (comma-separated `http(s)://host[:port]`).
- A request without an `Origin` that the browser marks as cross-site is refused.

Native clients that send no `Origin` (MCP over the daemon, the editor clients, the hooks, `curl`) are unaffected. Refusals are HTTP 403.

### `sparql` is bounded and better described

`sparql` results stop at 1000 rows, with the result marked `truncated`, and a query stops after 10 seconds. `FROM`, `FROM NAMED`, `SERVICE` and updates are rejected. To choose graphs, use `GRAPH <iri> { … }` for one or `GRAPH ?g { … }` to range over them. The tool description now lists the term namespace of every loaded ontology, and a parse error names an undeclared prefix. An empty result from a query that uses terms no graph contains comes with a note suggesting the terms that are in use.

### Every enclosing component governs a file

A file used to be governed only by the most specific component whose paths contain it. Now every covering component governs it:

- The most specific component is still the one the file `realizes`.
- Broader components, including a whole-project `.` path, also apply. They appear in dossiers under **Via enclosing component …**.
- Dossiers read a file's components from the declared coverage when they are read. A component declared, split or moved therefore takes effect at once, without re-minting.
- `validate_against_architecture` warns, without failing, about component paths that match no file.

### Dossiers carry claims

`get_entity_dossier`, editor hover and policy pushes now show the full claim of each record linked directly to the entity, not only its title. Component-level records stay as titles. Accepted Constraints are always listed, and other kinds are capped per component.

`evaluate_policy` accepts `max_bytes` for pushed dossiers. The first entity section is always whole. A later section that does not fit is shortened to its direct records and Constraint titles, never dropped, and a closing line names the shortened entities. The Claude Code push hook uses this, and cuts at a line boundary with an explicit truncation notice rather than mid-record.

### Supersession integrity

- `relate` refuses a `supersedes` edge from any record that is not `proposed`, and refuses `isSupersededBy` outright. A bare `supersedes` edge used to leave the replaced record `accepted`, so recall kept returning it as current. Use `supersede_decision` to replace a record.
- `validate_against_architecture` reports existing supersessions whose replaced record was never retired. A pending proposed supersession is exempt, since ratifying it does the retiring.

### Recall leaves out retirement notes

A retraction attaches a Rationale explaining why the record went. `get_relevant_context` no longer returns a Rationale whose only role is explaining retired records, so such notes stop crowding topic recall. `include_history` brings them back, and they remain available to `sparql` and to `query`'s evolution questions.

### Smaller changes

- **Durable export.** The canonical `kg.nq` export is serialized and fsynced, so concurrent writes cannot publish an older snapshot over a newer one, and a crash leaves `kg.nq` and its stamp consistent. Lifecycle and proposal writes no longer interleave with an accept or reject in the review inbox.
- **New ontology relations.** `restates` and `refines` relate one record to another under PROV.
- **Python projects without a manifest.** A Python project is indexed when a directory at the repository root holds `__init__.py`.
- **Wildcard binds.** A daemon bound to `0.0.0.0` publishes a connectable loopback address for `--status`, `ui`, and the hooks.
- **ADR skill fix.** The `generate-adrs-from-graph` skill now queries the current architecture namespace. Before this fix it found no decisions in any graph and reported that none had been recorded.

## Upgrading

No graph or vector-store migration is needed. Existing stores open unchanged.

- **Browser clients on another origin.** A web page served from a different origin than the daemon, such as a development server, is now refused with 403. Add its origin to `MOOSEDEV_ALLOWED_ORIGINS`.
- **Workbench chat sessions.** Sessions saved by v0.12.0 cannot be read by an earlier version.
- **Copied skills.** If you copied `generate-adrs-from-graph` into a project, copy it again to pick up the namespace fix.
