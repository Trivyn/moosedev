# MOOSEDev v0.13.0

v0.13.0 keeps recorded knowledge attached to code when the code moves, restores TypeScript indexing, and keeps unratified records out of the workbench chat.

## Highlights

### Moved code keeps its knowledge

A crate split or a module move used to strand the existing code entities. The SCIP symbol carries the crate name, so after the split the old entity never matched the code again. Every decision or constraint linked to it stayed attached to code that no longer existed, and a dossier at the new location left those records out.

`moosedev mint` now re-homes moved entities in place. The entity keeps its identity and takes the new path and symbol, so its record links and judgments follow the code:

- **Automatic** when a definition moved into another crate or package under a different directory prefix, for example `src/rdf/x.rs` → `crates/rdf/src/rdf/x.rs`.
- **`moosedev mint --remap OLD=NEW`** handles a move that also changed the module path. The flag can be repeated.
- **Never a guess.** An entity with more than one possible successor is listed under *not re-homed*, with its candidates.
- **Orphans with knowledge are listed.** The report lists every entity whose code is gone but that records still point at, with those records, so they can be relinked with `link_code`.

### TypeScript is indexed again

scip-typescript 0.6 began reporting positions in UTF-16 units, and the index rejected its output. TypeScript was therefore missing from the code substrate, and the only trace was a line in `.moosedev/index.log`. `moosedev index` now converts UTF-16 and UTF-32 positions to UTF-8 at index time. It is also more exact than before on lines with non-ASCII characters.

When a producer fails, `moosedev index` now prints the warning and ends with a `NOT INDEXED: …` line naming the code that is missing. The exit status stays 0, because the other languages' index is still published.

### Workbench chat answers from accepted knowledge

Chat in the web workbench used to read the whole store, so proposed and rejected records could shape its answers. Each chat turn now reads a view that hides them, as `query` already did. Chat sessions are still saved as before.

### Component paths can be removed

The new `remove_component_paths` tool removes paths from a component's declared coverage. It is idempotent and reports which paths were removed and which were never declared. After a move, declare the new path with `declare_component_paths` and drop the old one with `remove_component_paths`. The "component path matches no file" warning then clears.

### Smaller changes

- **Withdrawn replacements.** `validate_against_architecture` no longer reports a record as not retired when the record that would replace it was retracted, rejected or is still proposed. `examples/repair_unflipped_supersessions.rs` applies the same rule.
- **Ratifications inbox.** The inbox can sort by priority (the default), newest, oldest or name, and a filter box matches any field the page shows, including short record ids.
- **Ratify from the record.** A proposed record's own page has Accept and Reject buttons. For a proposed replacement, the page also shows the record it would supersede, the reason and the change.

## Upgrading

No graph or vector-store migration is needed. Existing stores open unchanged, and the engine is still MOOSE v0.29.0.

- **Re-index, then review a mint dry run.** Run `moosedev index`, which picks up TypeScript again where it had been dropped, then `moosedev mint` without `--apply`. Check the re-homes, *not re-homed* entries and orphans carrying knowledge before you apply.
- **Scripts that read `mint` output.** The `summary:` line has new fields: `rehome`, `not-rehomed` and `orphaned-with-knowledge`.
